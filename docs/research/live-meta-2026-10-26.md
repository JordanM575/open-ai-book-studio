**Date:** 2026-10-26
**Command:** `bun run live:check` (after `bun run build`)
**Specs:** [017](../../specs/017-voice-and-background/tasks.md) T012a, [019](../../specs/019-illustrations/tasks.md) T010a, [020](../../specs/020-sam-cutout/tasks.md) T008, [022](../../specs/022-provider-compatibility/tasks.md) T008

## What it proves

Four things that had only ever been tested against a mock now have real evidence, and one that
still does not.

| Check | Result |
| --- | --- |
| The model catalogue | **ok** — nine models on this key |
| A real writing turn | **ok** — the agent replied and the chapter file on disk changed |

## The endpoint

The base URL is **`https://api.meta.ai/v1`**. The studio's own speech module already defaults to
`https://api.meta.ai`, and the docs agree. A `.env` that says `api.meta.com` is a typo that
`getaddrinfo` will refuse with `ENOTFOUND` before any request is made.

`GET {base}/models` returns the catalogue, so the app's existing model-list path works unchanged:

```
muse-image-1.0, muse-spark-1.1, muse-spark-1.2, muse-spark-1.2-contributor,
muse-spark-1.3, muse-spark-1.3-contributor, muse-voice-transcribe-1.0,
muse-wonder-1.0, sam-3.1
```

## A writing turn

The run used the app's own `AgentRuntime`, the app's own tool set and the app's own adapter, on a
**temporary copy of the committed sample** with the book's Contributor consent set to true. The
pass condition was not "the agent replied" but "the file on disk changed", because a reply alone
proves nothing about a writing tool:

```
[live] ok  a real writing turn — the agent replied (280 characters) and the file on disk changed
```

The agent read the chapter, called its tools, and added a paragraph. No author data was used: the
sample is the project's own synthetic work, and the copy was deleted afterwards.

## Dictation

The check does not ask a human to speak, because then the transcript cannot be scored. It speaks a
known phrase with macOS `say`, converts it to the 16 kHz mono 16-bit WAV Meta accepts with
`afconvert`, and measures the transcript against the phrase:

```
[live] ok  dictation — "the lighthouse keeper counted the ships that never came." — 100% of the words (9 of 9), 3040ms of audio
```

`say --data-format=LEF32@22050` refuses to open its output file on this macOS ("Opening output file
failed: fmt?"). Dropping the flag and letting `afconvert` do the conversion works.

## SAM 3.1, and why it is not a parser bug

The request reaches Meta and is accepted:

- `POST https://api.meta.ai/v1/responses`, model `sam-3.1`, `input_image` as a base64 data URL,
  `input_text` as a short noun phrase — which is what Meta's own
  [segmenting guide](https://dev.meta.ai/docs/sam/segmenting) documents, and what
  `apps/desktop/src/main/segmentation.ts` already sends.
- The answer is `200` with `status: "completed"`, `error: null`, and
  `output[0].content[0].text === ""`.
- **No records and no `usage` at all.**

That was true for the sample's 1024×1024 illustration, the sample's 512×512 cutout, and a
synthetic 256×256 white disc on black, with the prompts "person", "lighthouse", "circle" and
"character". A public image URL was refused with `400`, which is a separate matter but did not
change the conclusion.

A completed response with no usage is the signature of a model that did not run for this key,
rather than of a request the studio got wrong. `sam-3.1` is in the catalogue, so the listing and
the entitlement disagree. **The next step is the Meta console, not the code.**

The live check now reports this as `blocked` rather than `failed`, with that reasoning in the
detail, because the distinction matters: one of the two is the studio's problem.

## The trap worth remembering

The first live run failed every check that called Meta, while the same requests succeeded from a
shell. The cause was not the studio and not the key:

```
NODE_OPTIONS=--import=…/headroom/providers/opencode/hook-shim/handler.js
HEADROOM_PROXY_URL=…
```

The coding agent's shell installs a `fetch` shim that routes outbound requests through a proxy
that authorises the agent's own traffic. Every check script spawns the app with
`{ ...process.env }`, so the app inherited the shim, and every provider request came back as
`{"error":"unauthorized"}` — an error that looked exactly like a bad key.

All the check scripts now scrub `NODE_OPTIONS` and the `HEADROOM_*` variables before spawning the
app. The checks must run the app in a clean environment, or they measure the agent's proxy instead
of the product.
