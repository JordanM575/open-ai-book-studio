# Illustrations: image storage and Muse Image generation

**Status:** Planned (2026-10-26)
**Number:** 019
**Depends on:** [002](../002-studio-v1/spec.md) library/archive, [011](../011-model-access/spec.md) Meta
connection, [018](../018-agent-toolkit/spec.md) backend if the toolkit should see images later.

## Why

An author should be able to illustrate a chapter without leaving the book folder. The image is a file
the author owns, next to the manuscript, with enough metadata to know what produced it and enough
provenance to regenerate or remove it. The first version uses one Meta image model and one prompt
surface; it is not a general image editor.

## User stories

1. **Illustrate a chapter.** Open the Illustration panel, write a prompt, see the estimated cost, press
   Generate, and see the image in the chapter. The PNG is saved under the book folder.
2. **Keep the provenance.** Reopening the book shows the image, its prompt, model, dimensions and date.
   The manifest is ordinary JSON, not a hidden database.
3. **Regenerate deliberately.** A second generation creates a new image; the old file is not
   overwritten. The author chooses which image to attach to the chapter.
4. **Fail without a cost surprise.** A missing Meta connection, a rejected key, a safety refusal or an
   offline request leaves the book unchanged and says what failed. The estimate is visible before the
   request.
5. **Move the book.** Export the library as an archive and import it elsewhere; the images and manifest
   arrive with the Markdown.

## Requirements

### Image format

- **FR-001** Images live under `books/<bookId>/images/` with a versioned `books/<bookId>/images.json`
  manifest. Image bytes are never embedded in `book.json`.
- **FR-002** An image record has: `id` (`img_…`), `kind` (`chapter`, `character`, `cover`, `other`),
  optional `chapterId` and `characterId`, `fileName`, `mimeType`, `width`, `height`, `bytes`,
  `sha256`, `prompt`, `provider`, `model`, `size`, `source` (`generated` or `imported`), `createdAt`,
  optional `cutoutOf`, optional `costUsd` and optional `revisedPrompt`.
- **FR-003** The file name is generated by the studio and ends in the detected format
  (`.png`, `.webp`, `.jpg`). The manifest never stores an absolute path.
- **FR-004** The image file is written first to a temporary sibling and renamed into place; the manifest
  is written atomically after it. A failed manifest write leaves an orphan file that is reported and
  can be adopted or removed; it is never shown as a saved image.
- **FR-005** A missing or corrupt manifest yields an empty gallery with a warning. The studio does not
  delete image files to repair the manifest.
- **FR-006** The manifest and image bytes are included in the portable archive, hashed like every other
  author file and preserved on import. Unsupported future manifest versions are reported, not
  silently rewritten.
- **FR-007** Limits: one image per generation, 20 MB per image, PNG/WebP/JPEG only, and a 1–4,000
  character prompt. The studio detects the real format from the bytes rather than trusting a MIME
  header.

### Generation

- **FR-008** Generation uses the author's Meta connection and
  `POST https://api.meta.ai/v1/images/generations` with `model: "muse-image-1.0"`, `n: 1`,
  `response_format: "b64_json"`, `output_format: "png"` and a documented `size` aspect ratio.
- **FR-009** The service MUST show a `$0.01` estimated cost before the request and record the actual
  provider usage when returned. No image is requested without an explicit author action.
- **FR-010** The service MUST validate the base64 payload, detect the image format and dimensions, and
  reject bytes that are not a complete image before writing anything.
- **FR-011** A content-policy refusal, 429, 5xx or network failure is normalized into one author-readable
  sentence. The book and manifest are unchanged.
- **FR-012** The prompt and image go only to the configured Meta endpoint. No studio server, telemetry,
  URL fetch or archive upload receives them.
- **FR-013** Generation is desktop-first. The web build may show the panel only after Meta browser access
  is verified; otherwise it explains the desktop requirement.

### Interface

- **FR-014** An Illustration panel for the selected chapter offers a prompt, a size choice, the model
  and estimated cost, Generate, preview, Attach and Regenerate. It uses the existing dialog and token
  system.
- **FR-015** The panel shows generating, saved, failed, refused and no-connection states. Reduced motion
  and transparency are respected; the manuscript remains usable while a generation runs.
- **FR-016** The attached image is visible in the workspace and recorded on the chapter. A chapter may
  have one attached illustration in v1; generating another creates an image record and lets the author
  switch.
- **FR-017** DOCX export embeds the attached chapter image after the chapter body with a caption
  containing the prompt, or omits it with a warning if the file is missing. The export never fails
  because of an optional image.

## Non-goals

- Multi-turn image editing, reference-image composition, masks or inpainting.
- A general asset manager, folders, tags or bulk import.
- Image search, stock photos, external URL downloads or generated-image sharing.
- Character portraits and covers beyond the record kinds; the UI can add them later.
- A hosted image service or a studio-owned storage bucket.

## Acceptance scenarios

1. **Generate.** With a Meta connection, generate a 1024×1024 chapter image. The panel shows the
   estimate, the PNG appears, `images.json` has one record, and the file exists under `images/`.
2. **Regenerate.** Generate again with a new prompt. Two image records and two files exist; the chapter
   attachment changes only when the author chooses it.
3. **Refusal.** A prompt rejected by the provider leaves the manifest and folder unchanged and shows one
   sentence.
4. **Corrupt manifest.** Replace `images.json` with invalid JSON, reopen the book. The gallery is empty
   with a warning; the image files are still on disk.
5. **Archive.** Export after generating, import into an empty library. The image bytes, manifest and
   chapter attachment are present.
6. **Export.** Export DOCX with an attached PNG. The document contains the image; deleting the file
   first produces a warning and still exports the text.

## Open decisions

- **D-130** Image manifest vs extending `book.json`: a separate `images.json` is recommended for size,
  merge behaviour and a clean archive diff. Accepted by author direction on 2026-10-26; implementation
  follows this spec.
- **D-131** Image editing and reference images: deferred until the one-shot generation and cutout flows
  are reliable.
