# Tasks: manuscript-file import

**Spec:** [spec.md](spec.md) · **Plan:** [plan.md](plan.md)  
**Status:** Draft — all 18 tasks are checked; implementation and verification are recorded per task. Word (DOCX) intake is enabled on the macOS reference target by D-183 (T018). Acceptance of the bounded desktop profile and any further format or target enablement remain separate decisions.

Tasks are ordered. Resolve each open decision before only the task(s) it blocks; an open question does not block independent parser scaffolding or test work.

## Phase 0 — Resolve the proposed contract

- [x] T001 Accept or revise the split, title and Markdown behavior in spec open decision 1. Record the public outcome before implementing parser semantics or preview controls. This blocks T005–T007, not IPC scaffolding or library-port test scaffolding. Decided 2026-11-03 with the author: the proposal stands — whole-file default, author-selected line-boundary splits, Markdown literal, filename-derived editable title. Recorded in spec.md decision 1.
- [x] T002 Set and document maximum source bytes, line/segment limits, BOM behavior, NUL/control-character handling and empty-file behavior using synthetic fixtures and a resource review. This blocks production source reads and parser limit enforcement in T005/T008, not the static UI shell. Decided 2026-11-03 with the author: 5 MiB max source (conservative against proven 15MB IPC round-trips), strict UTF-8, strip one leading BOM, reject NUL/control characters, refuse empty input. Recorded in spec.md decision 2.
- [x] T003 Verify whether the existing desktop `LibraryPort.moveDirectory` can atomically publish a complete staged book on each proposed target and define cleanup behavior. If it cannot, settle the port primitive or supported-target restriction before writing the importer. This blocks T009, not pure parsing or preview work. Verified 2026-11-03: the desktop adapter renames within one volume (atomic on the macOS reference target); cross-device moves are refused with `unsupported` rather than copied; `removeDirectory` was added to the port with desktop, in-memory and web-stub implementations for unpublished staging cleanup. Conformance covered by `packages/core/tests/library-port.test.ts` and `apps/desktop/tests/library-publish.test.ts` (same-device staging asserted). Web copy+delete does not qualify for atomic publication, so the first profile's publisher stays desktop-gated per FR-024.
- [x] T004 Decide the first desktop OS capability matrix. Keep the import action disabled on every unverified target; macOS reference status alone does not establish Windows/Linux support. This blocks platform enablement and acceptance in T012, not shared-core work. Decided 2026-11-03: macOS-only initial. The atomic-rename publication evidence (T003 conformance) and picker/read boundary tests run on the macOS reference target; Windows and Linux stay disabled until their native rename, dialog and staging behavior is verified the same way. Recorded in spec.md decision 4.

## Phase 1 — Parse and preview without writing

- [x] T005 Add the pure first-profile input validator/parser in `packages/core/src/manuscript-import/`. Implement only the accepted input and split contract; tests use synthetic UTF-8 TXT/Markdown fixtures and cover exact line assignment, Unicode, canonical newline handling, invalid encodings and accepted limits. Depends on T001 and T002 for the behaviors they decide. Implemented `validateSource` (extension, 5 MiB, strict UTF-8, one BOM, NUL/control rejection, empty refusal) and `previewImport` (whole-file default, ordered line-boundary splits, canonical bodies, per-chapter edge-blank-line accounting, Markdown literal). Covered by `packages/core/tests/manuscript-import.test.ts` (11 tests: acceptance, refusals, Unicode, CRLF/CR/mixed, literal Markdown, exact line mapping).
- [x] T006 Define the preview/mapping/report types in shared core: editable book title, ordered chapter titles and contents, explicit split boundaries, counts and normalization notes. Assert that preview output is derived deterministically from the accepted source bytes, contains no omitted or duplicated nonblank text, and identifies edge blank-line normalization. Depends on T001. The `ImportPreview` family was defined with T005; this slice adds the determinism assertion (split order is irrelevant) and the span-reconstruction invariant (every body equals its source span minus the reported edge blanks, which must really be blank). Covered in `packages/core/tests/manuscript-import.test.ts`.
- [x] T007 Add component tests for full-text preview, title editing, split-point editing, unsupported-format copy and cancel-before-confirm behavior using synthetic fixtures. Verify that the library API has not been called before confirmation. Depends on T001; does not depend on platform-specific source reads. New presentational `ImportPreviewDialog` (`packages/app/src/components/ImportPreviewDialog.tsx`): full-text chapter preview with line ranges and word counts, editable book/chapter titles, add/move/remove split controls that re-derive chapters from the same source bytes, refusal copy for unsupported input, and normalization notes. It reports the confirmed mapping through `onConfirm` only and imports nothing from the library or IPC. Covered by `apps/desktop/tests/manuscript-import-preview.test.tsx` (9 tests, including a source scan asserting no library/IPC import); registered in `tsconfig.web.json`/`tsconfig.node.json`.

## Phase 2 — Stage one complete book

- [x] T008 Implement the desktop main-process picker and source-read boundary. Validate the chosen extension and accepted byte limit in main, use strict decoding, keep host paths out of renderer inputs, and return a typed refusal on cancel, missing file, unsupported input or read failure. Unit tests use synthetic files in isolated temporary directories. Depends on T002; picker exposure depends on T004. Implemented in `apps/desktop/src/main/import.ts`: `pickImportSource` (injected dialog, macOS-gated per T004, cancel without refusal) and `readImportSource` (stat-first size refusal, extension pre-check with shared core wording, strict core validation, file-name-only refusals). Covered by `apps/desktop/tests/manuscript-import.test.ts` (9 tests); the `./manuscript-import` export was added to `packages/core/package.json`.
- [x] T009 Add a dedicated library operation that writes a complete book under a unique unpublished staging path, validates/read-backs `book.json` and every chapter, and publishes with one atomic directory move. Add fault-injection tests for each write, validation, publish and cleanup failure using an in-memory port and isolated temporary library. Never implement this as sequential visible `createBook`/`createChapter` calls. Depends on T003. Implemented `LibraryService.importManuscript` (`packages/core/src/library/service.ts`) with staging path helpers in `packages/core/src/library/paths.ts`: unique `.studio/staging/<bookId>/` write, schema + content read-back of `book.json` and every chapter, single `moveDirectory` publication, then layout/catalog/read-back. Failures clean up staging (cleanup failure names the remaining staging path) and never leave a visible book. Covered by `packages/core/tests/manuscript-import-publish.test.ts` (6 tests: exact mapping, write/validation/publish/cleanup failures, empty refusal, no `books/` writes before the move).
- [x] T010 Wire the typed import operation through `packages/core/src/ipc.ts`, desktop IPC validation/handlers and the preload bridge. Validate request sizes and mapping shape; expose no arbitrary renderer-supplied filesystem path. Tests assert the main process is the only source/library writer. New `books:importManuscript` channel with `ImportManuscriptInput` in `StudioApi`; the `importManuscriptInputSchema` lives in shared core (strict objects reject smuggled paths; at most 200 chapters, 6M chars each) and the desktop handler parses every payload with it before delegating through a new `Library.importManuscript`. The preload bridge exposes it (typed by `StudioApi`), and the web runtime refuses it honestly as desktop-only per T016. The preview dialog's confirmed mapping is now typed as the IPC input (titles + full bodies, no path), so main can publish statelessly. Covered by schema accept/reject tests in `packages/core/tests/manuscript-import.test.ts` and a dialog-to-contract test proving the confirmed mapping parses with exactly `bookTitle` + `chapters` keys.

## Phase 4 — Deferred format and host work

These items are not gates for the bounded TXT/Markdown profile. They remain unchecked and must not appear as supported until their own format or host checks pass.

- [x] T014 Plan and validate DOCX intake separately from DOCX export. Define parser support, chapter-boundary behavior and rich-structure loss reporting with synthetic documents before enabling the extension. Current evidence: `specs/029-manuscript-import/research/docx-intake.md` records the verdict (mammoth body conversion plus fflate zip sniffing; `docx@9` exports no reader; manual OOXML rejected) and the validated contract (non-title top-level headings are chapter boundaries; body wording survives; images refused via convertImage override, never base64; table cell text in document order; headers/footers/footnotes sniffed and reported as loss). `apps/desktop/tests/docx-intake-validation.test.ts` proves each clause with in-test synthesised documents (7 pass); the product path still refuses `.docx`, pinned by the same file. The intake feature itself is not enabled: no IPC, UI or format change; enabling needs a format decision, the plain-text transform, staged-publication wiring and T013 conformance. Enabled 2026-11-03 by D-183; see T018. Enabling corrected one finding: mammoth does convert footnotes and endnotes, so the intake removes their marks and appended text and reports each one.
- [x] T015 Evaluate DOC, RTF and ODT individually with format-specific synthetic fixtures and explicit parser/normalization decisions; do not treat these formats as implemented by the TXT/Markdown path. Current evidence: `specs/029-manuscript-import/research/other-formats-intake.md` records the verdicts (RTF rejected: `rtf-parser@1.3.3` throws on `\pict` images and legal `\ ` escaped spaces, silently inlines headers/footnotes as body text, silently flattens tables; `@iarna/rtf-to-html` throws on the same input. ODT validated but not enabled: `fflate` zip layer plus `fast-xml-parser@5.11.2` with mandatory `preserveOrder:true` + `trimValues:false`, outline-level-1 headings as chapter boundaries, table cells in order, image hrefs without bytes, footnotes distinct, headers/footers in `styles.xml` sniffed as loss. Legacy `.doc` refused: `word-extractor` unvalidated, no synthesizable fixture path, no local converter). `apps/desktop/tests/other-formats-intake-validation.test.ts` proves each clause with in-test synthesised fixtures (10 pass); the product path still refuses `.doc`, `.rtf` and `.odt`, pinned by the same file. No intake is enabled: RTF/DOC stay refused, ODT enabling needs a format decision, the plain-text transform, staged-publication wiring and T013 conformance.
- [x] T016 Specify and test a separate browser/mobile source-selection and publication capability for web folder access, browser storage, iOS and Android. Keep these targets unavailable until they can meet the source-read and complete-publication contract. Current evidence: `specs/029-manuscript-import/research/browser-mobile-import.md` records the per-target verdict (web folders: source read possible but every web port is `DirectoryHandleLibraryPort` whose `moveDirectory` is copy+delete, so a crash mid-publish leaves a partial tree; browser storage: same port blocker plus no validated picker source path; iOS/Android: the Capacitor shell serves `../web/dist` with no native writer, inheriting the refusal). `apps/web/tests/storage/manuscript-import-refusal.test.ts` pins the honest refusal on both channels (3 pass: typed `invalid` failure naming the desktop app, never a throw, library untouched). Per-target enablement needs a validated source read, a failure-clean publish primitive with fault-injection tests, and a T013-style hidden-journey gate; FR-024 stays desktop-gated.
